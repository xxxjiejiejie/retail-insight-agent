# 5 分钟面试演示流程

这套流程面向 AI 应用开发实习面试，使用真实模式展示工程链路；如果现场网络或模型额度不稳定，切换 `http://localhost:8080/?demo=1`，但要明确说明演示数据不代表真实模型评测。

## 0:00-0:30 项目定位

一句话说明：这是一个面向零售企业的 LangGraph 智能体，把结构化经营数据库查询和制度知识库问答放在同一套可审计工作流中。

先指出页面顶部的三个状态：API、经营数据库、制度知识库。强调数据、引用、SQL 和运行指标都能回看。

## 0:30-1:20 SQL 安全查询

输入：`2026年6月各门店销售目标完成率是多少？`

展示四件事：

1. 结果表和图表；
2. 生成 SQL 与只读 SQL 校验结果；
3. 查询耗时、Token 和返回行数；
4. Schema 字段来自后端元数据，不是前端写死。

面试表达：SQL 不是直接执行模型文本，而是经过 JSON 计划、SQLGlot AST、表字段白名单、危险节点检查、LIMIT、超时和只读执行。

## 1:20-2:00 RAG 制度问答

输入：`普通商品无质量问题可以在多少天内退货？`

打开制度依据，展示文档版本、章节、段落和原文引用。

补问库外问题：`公司的差旅住宿标准是多少？`，展示低相关度拒答和零引用。说明 RAG 的核心不是“总要回答”，而是证据不足时拒答。

## 2:00-2:40 Hybrid 联查

输入：`查询2026年6月各门店销售目标完成率，并说明绩效制度中的指标权重。`

展示 SQL 结果和制度引用同时返回。说明 LangGraph 将数据子问题与制度子问题拆分并行，最后合并为一个可解释答案。

## 2:40-3:20 上下文追问

连续输入：

1. `2026年6月各门店销售目标完成率是多少？`
2. `只看未达标门店`
3. `换成五月`

展示第二轮的 `context_used`、`resolved_query` 和会话历史。说明追问先由确定性规则把短问题与最近分析轮次合并，再进入原有 SQL/RAG/Hybrid 分支，不额外增加一次“判断上下文”的 LLM 调用。

## 3:20-4:10 失败样本和故障恢复

进入“评测结果”，打开失败样本：

- SQL 响应解析失败；
- Top-N 结果边界；
- 结果值语义比较；
- RAG 库外问题引用噪声。

再展示故障恢复专项的 3/3：LLM API 超时安全降级、格式异常自动重试、数据库超时按上限结束。强调失败被记录、分类和保留，而不是改成通过。

## 4:10-5:00 批次对比和收尾

在评测页选择当前批次和上一批次，展示：

- SQL、RAG、Hybrid 准确率、拒答率、Token、P50/P95 延迟；
- 正常集与挑战集分开统计；
- 多轮和故障专项单独统计；
- 优化说明、指标变化和已知限制。

最后用三句话收尾：

1. 我能解释每个答案从哪里来；
2. 我能用真实失败样本定位问题，而不是只展示成功截图；
3. 我明确区分本地门禁、真实模型端到端结果和仍未覆盖的生产能力。
